# Architecture

## Monorepo

```
apps/
  desktop/              Tauri 2 app: React UI (src/) + Rust core (src-tauri/)
packages/
  protocol/             FaceFrame: the one tracking data shape for every source
  model-format/         Model JSON schema, validator, SPEC.md
  engine-2d/            PixiJS renderer: parameters in, pixels out
  ui/                   Design tokens, shared components, RU/EN strings
assets/sample-models/   Bundled sample models "Lumi" and "Kuro" (SVG), generated by scripts/sample_models
scripts/                Repo scripts (MediaPipe asset download)
docs/                   Plan, architecture notes
```

`apps/mobile` (Expo, phone tracking) is the next phase. It only has to send
`FaceFrame`s; nothing on the desktop side changes for it.

## Data flow per frame

```
camera ─▶ MediaPipe ─▶ FaceFrame ─▶ TrackingHub ─▶ inputs ─▶ AvatarFrameComposer ─▶ parameters ─▶ AvatarRenderer
(phone later) ──────────▶ FaceFrame ─┘   (calibrate,          (mapping, idle motion,
                                          sensitivity,         expressions, overrides,
                                          One Euro filter)     physics, clamp)
```

- **TrackingHub** (`contexts/tracking/application`) is the single entry for any
  source. Everything after it never knows where data came from.
- **AvatarFrameComposer** (`contexts/avatar/application`) turns inputs into model
  parameter values. It also implements **AvatarControlPort**.
- **AvatarRenderer** (`packages/engine-2d`) knows only parameters and the model file.

The doc plan put filtering and calibration in Rust. For the webcam they run in
TypeScript next to MediaPipe: sending each frame to Rust and back only adds
delay. When phone tracking arrives, Rust receives UDP frames and forwards them
to the same hub.

## Desktop app layout (DDD)

`apps/desktop/src/contexts/<context>/{domain,application,infrastructure,presentation}`

| Layer | Holds | May import |
| --- | --- | --- |
| domain | Pure rules and types (filters, mapping, physics) | nothing app-specific |
| application | Use cases, stores, services | domain, infrastructure |
| infrastructure | Camera, MediaPipe, Tauri commands, file pickers | domain |
| presentation | React components | application, domain |

Contexts: `tracking`, `avatar`, `scene` (stage, background, window), `settings`,
`debug`. `app/` is the composition root (`app_runtime.ts` builds the services once)
and the shell layout.

Rust (`src-tauri/src`) mirrors this: `model_library`, `media_library`,
`desktop_shell` (tray, click-through, file manager), `app_paths` (env config).

## Configuration

- Technical knobs: `.env` (see `.env.example`). UI values are `VITE_*`, read and
  validated in `src/config/app_config.ts`; Rust reads `VTUBEAREA_*`.
- Everything the user clicks is saved per user in local storage (Zustand persist):
  tracking settings, calibration, per-model placement and parameter mappings,
  background, language.

## Rules

- Names: snake_case for variables, functions and files; PascalCase for types and
  React components; camelCase only for React hooks (`useSomething`), because
  React's tooling requires it. No single-letter names except x/y/z/w.
- No file over 700 lines (ESLint `max-lines`).
- `pnpm check` must pass: lint, types, Vitest, cargo test.
